# 单／多环境回放一致性诊断

本文记录此前完成的诊断。后续目录清理已删除历史数据、诊断脚本与输出，
下列路径和复现命令属于历史记录，当前不能直接执行。修复代码仍保留；
新数据使用 `configs/runs/production.yaml` 生成，再通过公开 `replay` 命令验证。

日期：2026-09-09。真实 GPU 运行，Isaac Sim 6.0.1、TGS、120 Hz、64/4 次迭代。
诊断使用 `outputs/smoke/piper--matryoshka_00002`，保留原资产、世界坐标、
抓取命令、三轮种子和扰动数组；未修改摩擦、阶段时长或验收阈值。

## 根因与证据

原 `GraspScene.reset()` 只覆盖物体与夹爪的位置、速度和驱动目标，没有销毁
PhysX 的接触／求解历史状态。这样重复使用的场景不能视为独立试验；不同
批量布局下的内部数值差异会被带入后续接触，并改变临界候选的稳定性判定。
这里定位到的是应用层的重置生命周期缺陷；没有把差异进一步归因到某个
未公开的 PhysX 缓存字段或具体 CUDA 内核。

候选 `676920072347365623` 的对照结果：

| 重置方式 | 单环境三轮 | 16 环境中的三轮 | 批量第三轮末尾稳定时长 |
| --- | --- | --- | --- |
| 只写位置、速度、驱动目标 | 全通过 | 第三轮失败 | 0.125 s |
| 每轮创建独立物理场景 | 全通过 | 全通过 | 1.0 s |

原运行的第一轮物体姿态逐步完全一致。第二轮闭合时，第 2,694 个观测
（从零计数为 2,693）开始出现物体姿态和接触力差异；基座姿态始终一致。
第三轮翻转后保持阶段，双指最小接触力约 24.87 N，无接触丢失，最大相对
位移约 0.145 mm、旋转约 0.00841 rad。失败由物体角振荡打断连续稳定窗口
引起，要求是最后连续 0.2 s 稳定。`inversion_drop` 也涵盖这一阶段的稳定性
失败，不能从这个名称推断物体实际掉落。

只改变重置方式后，单／多环境三轮共 7,059 步的物体姿态、基座姿态、关节
位置、物体速度和接触力完全一致。原始关节速度最大差异约
`1.2666e-7 m/s`，未改变关节位置或验收判据。批量 16 条全部通过。
因此修复不承诺 GPU 所有读回通道逐位相同，也不把本次结果推广为任意
候选、任意世界坐标或求解精度下的确定性保证。

## 实现

公共 `GraspScene.reset()` 在已有试验状态时重建场景及 tensor views，第一轮
使用构造时创建的场景。该逻辑同时覆盖试验之间和候选批次之间的重置。
重建保留 audit 的质量／摩擦倍率；`GravitySlipScene` 使用相同的公共重置，
不再重复实现场景重建。该反例在重建前恢复正常摩擦倍率，只在保持阶段
临时降低摩擦；不能将上一轮保持阶段的低摩擦作为下一轮初始材质。
GUI 每轮重建后重新设置观察相机。

试验仍按原顺序执行全部阶段，不延长稳定时间、不跳过失败、不调整阈值。
代码身份已改变，因此旧任务不能直接 `--resume`；已有数据可以回放，
生成新任务应使用新的输出目录。原 smoke 分片及历史失败证据未修改。

## 复现与证据

以下 GPU 命令需要在沙箱外执行，并设置 README 中的运行环境变量：

```bash
.venv/bin/python outputs/consistency/diagnose.py \
  --run outputs/smoke/piper--matryoshka_00002 \
  --grasp-id 676920072347365623 --scope all --reset tensors \
  --output outputs/consistency/reproduce-tensors-batch
```

分别将 `--scope` 设为 `target`／`all`、`--reset` 设为 `tensors`／`scene`，
使用不同的输出目录完成四组对照。`tensors` 仅为诊断脚本复现旧重置行为，
不是正式生成／回放选项。
`--scope copies` 则按原生成配置的环境数复制同一个候选，保持所有输入相同，
用于隔离环境数量的影响。这些重复输入只用于诊断，不计为新增抓取数据。

- `outputs/consistency/baseline-{single,batch}/`：修改前原始回放与逐步状态。
- `outputs/consistency/fresh-{single,batch}/`：只改变场景生命周期的对照。
- `outputs/consistency/comparison.json`：通道差异、阶段指标与证据 SHA-256。
- `outputs/consistency/compare.py`：从上述数组重算对照报告，不使用 GPU。
- `outputs/consistency/cli/`：修复后正式 CLI 回放和反例结果。

最终数量以各报告的 `requested`、`passed`、`complete` 和反例结果为准。
本次验收不替代全物体生产、求解精度敏感性、长期运行或硬件验证。

已完成的正式回放：四组合各 16 条批量回放全部通过，共 64/64；Piper／套娃
00002 全部 16 条单环境三轮回放通过，耗时约 1,298 s。按候选 ID 比较，16 条
的输入、实际闭合姿态、每阶段状态、失败代码及所有阶段指标均与批量相同。
所有回放报告 `complete=true`，没有物理／渲染错误，worker 均释放 GPU。
逐条对照可通过 `outputs/consistency/summarize_cli.py` 重算，结果保存在
`outputs/consistency/cli/summary.json`。

单指反例三轮均在闭合阶段正确拒绝；重力滑落反例三轮均在重力保持阶段
正确拒绝。初次重力反例检查发现临时低摩擦被恢复到下一轮场景，第二／三轮
误通过；该结果保留在 `cli/audit-gravity_slip.json`。修正初始倍率恢复时机后，
正式 `cli/audit-gravity_slip-fixed.json` 完成且三轮均正确拒绝。

原生成规模的补充对照使用 64 个完全相同的候选输入，保持保存的世界坐标，
通过环境 ID 隔离接触。三轮 64/64 均通过，每个环境与单环境的 7,059 步
全部记录通道一致，包括原始关节速度。结果为 `fresh-64/`，逐通道对照为
`comparison-64.json`，可用 `compare_copies.py` 重算。这 64 个副本不计入数据量。

`reset-scales.json` 验证了两个夹爪各三次真实场景重置：质量／惯量倍率 1.2、
物体和夹爪摩擦倍率 0.8，在每次重建及物理步进后读取均正确。该属性检查
不等同于重新完成全部物理敏感性试验。Ruff 和 mypy 检查通过；未编写单元测试。
最终汇总见 `outputs/consistency/final-report.json`。
